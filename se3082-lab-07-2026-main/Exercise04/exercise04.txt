Exercise 4: Replace Gather with Reduce
=========================================

What was changed from Exercise 3:
- Removed the all_sums array and the manual summation loop on root.
- Replaced MPI_Gather with MPI_Reduce using MPI_SUM as the operation.
- MPI internally computes the sum using a tree-based algorithm in O(log P) steps,
  which is more efficient than root doing a sequential O(P) loop.
- After MPI_Reduce, the total_sum variable on root already contains the correct
  answer — no further computation is needed.

Compile and Run (on EC2):
  $ mpicc -o sum_reduce sum_reduce.c
  $ mpirun -np 4 ./sum_reduce

Sample Output (4 processes):
  Root filled array with values 1 to 1000000
    Rank 0: local_sum = 31250125000
    Rank 1: local_sum = 93750125000
    Rank 2: local_sum = 156250125000
    Rank 3: local_sum = 218750125000

  [Reduce] Total sum = 500000500000
  [Reduce] Expected  = 500000500000
  [Reduce] Correct?  = YES
  [Reduce] Time      = 0.0081 sec

Key Observations:
- MPI_Reduce is the most efficient approach when only root needs the result.
  It eliminates both the manual receive loop and the manual summation loop.
- The recvbuf (total_sum) is ONLY valid on root after MPI_Reduce.
  Non-root processes will have an undefined/garbage value in their recvbuf.
- If all processes need the result, use MPI_Allreduce (Exercise 5) instead of
  MPI_Reduce followed by MPI_Bcast.
- Available reduction operations: MPI_SUM, MPI_MAX, MPI_MIN, MPI_PROD, etc.
